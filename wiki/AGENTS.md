# wiki 에이전트 지침

이 파일은 `wiki/`와 모든 하위 폴더에 적용한다. [루트 지침](../AGENTS.md)을 함께 읽고, 자료 원본을 다룰 때는 [raw 지침](../raw/AGENTS.md)도 따른다. 건강 판단·목적 인터뷰·권한은 루트 지침, 주장별 인용은 [출처 양식](../templates/source.md)이 단일 기준이다.

## 시작과 폴더 구조

[목차](index.md), [로그](log.md)의 상단 최신 기록, 작업과 관련된 실제 페이지를 읽는다. 개인화할 때만 프로필·대시보드와 해당 기간의 기록·계획을 추가로 확인한다.

```text
wiki/
├── AGENTS.md                   폴더 운영 지침
├── index.md                    전체 페이지 목차
├── log.md                      최신 기록이 앞에 오는 추가 전용 작업 이력
├── sources/                    자료별 출처·열람 범위·검증 상태
├── topics/                     여러 출처를 연결한 주제 지식
├── queries/                    질문별 답변·비교·검색 이력
├── plans/                      개인 실행 계획과 상태 변경 이력
├── workouts/                   종목별 운동 기록과 안내
│   ├── index.md                등록 종목·양식·실제 운동 기록 목록
│   ├── crossfit/               크로스핏 Markdown 기록
│   └── climbing/
│       ├── analysis-videos/    등반 분석 영상·이미지 저장(Git 추적 X)
│       ├── pathfinding-images/ 패스파인딩 분석 저장(Git 추적 X)
│       ├── records/            클라이밍 Markdown 기록
│       └── assets/             클라이밍 사진·영상 첨부
└── monitoring/
    ├── profile.md              확인된 개인 사실·목표·선호
    ├── dashboard.md            현재 상태와 다음 확인 사항
    ├── daily/                  사건 날짜별 관찰 기록
    └── reviews/                회고일별 기간 분석
```

## 파일별 작성과 수정

아래 파일명 패턴은 앞으로 생기는 모든 파일에도 적용한다. 실제 파일 각각의 링크와 한 줄 설명은 [index.md](index.md)에 유지한다. 새 파일을 만들 때 목차에 설명을 추가하고, 목적이나 상태가 달라지면 그 설명도 수정한다. 개별 출처 목록을 이 지침에 중복 관리하지 않는다.

| 파일·패턴                          | 담는 내용                                      | 작성·수정 지침                                                                                                                                                                                             |
| ---------------------------------- | ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AGENTS.md`                        | 이 폴더의 구조와 파일 관리 규칙                | 운영 변경에 맞춰 수정한다. 건강 지식이나 작업 결과를 저장하지 않는다. 루트·README와 충돌하는 안내도 함께 맞춘다.                                                                                           |
| `index.md`                         | 모든 실제 위키 페이지의 링크와 파일별 설명     | 개인 모니터링·주제·질문·계획·출처·운영으로 분류한다. `pending` 출처는 대기 목록에 둔다. 없는 페이지에는 링크를 만들지 않는다.                                                                              |
| `log.md`                           | 작업·근거·변경 페이지·미해결 사항              | 아래 추가 전용 규칙을 따른다. 일반 문서처럼 기존 내용을 정리하거나 교정하지 않는다.                                                                                                                        |
| `sources/YYYY-MM-DD-짧은제목.md`   | 자료 하나의 식별 정보·목적·주장·열람 위치·한계 | [출처 양식](../templates/source.md)을 사용한다. DOI·PMID 등으로 중복 확인 후 생성한다. 목적 확인 전 `pending`, 확인 후 `integrated`. 재열람·교정·철회로 판단이 바뀌면 이전 판단과 변경 근거·날짜를 남긴다. |

| `queries/YYYY-MM-DD-주제.md`       | 질문·핵심 답변·근거 비교·실제 검색 이력        | [질문 양식](../templates/query.md)을 사용한다. 같은 질문은 기존 분석을 갱신할 수 있다. 결론 변경 시 이전 결론·새 근거·변경일을 남긴다. 사용자가 저장하지 말라고 한 답변은 만들지 않는다.                   |
| `plans/계획명.md`                  | 목표·행동·관찰 지표·조정 기준·실행 상태        | [계획 양식](../templates/plan.md)을 사용한다. 요청받은 계획만 `draft`로 작성하며 시작 의사가 확인되면 `active`로 바꾼다. 수정·중단·완료의 날짜와 이유를 이력에 남긴다.                                     |
| `monitoring/profile.md`            | 사용자에게 확인한 사실·목표·선호·미확인 항목   | 진술 날짜나 원본을 붙인다. 정정 시 이전 값·새 값·근거를 변경 이력에 보존한다. 관심 주제를 실제 증상·진단으로 바꾸지 않는다.                                                                                |
| `monitoring/dashboard.md`          | 확인된 목표·활성 계획·최근 관찰·재평가         | 실제 기록과 상태가 변할 때 갱신한다. 상세 내용은 해당 페이지로 연결하고, 없는 통계나 추세를 만들지 않는다.                                                                                                 |
| `monitoring/daily/YYYY-MM-DD.md`   | 실제 사건 날짜별 식사·통증·측정과 운동 연결    | [일별 양식](../templates/daily.md)을 사용한다. 운동 상세는 workouts의 해당 세션에 연결한다. 기존 운동 접수 기록은 보존하며 중복 집계하지 않는다. 같은 날짜의 추가 입력은 시간·세션으로 구분한다.           |

| `workouts/종목/`                   | 종목별 Markdown 운동 기록과 첨부               | [운동 기록 스킬](../.agents/skills/workout-log/SKILL.md)과 등록 양식을 따른다. 클라이밍은 records와 assets를 분리한다. 첨부 원본은 보존하고 실제 파일만 상대 링크로 연결한다.                              |

## 공통 작성 기준

- 기본은 한국어 Markdown이며 크로스핏 등 사용자가 지정한 종목 양식의 언어·배치는 해당 형식을 따른다. 주요 전문 용어는 첫 등장에 영어를 병기한다. 일반 페이지의 YAML은 `type`, `created`, `updated`, `status`, `tags`를 채운다. `created`는 최초 작성일을 유지하고 수정일은 `updated`에 반영한다. 사건 날짜·기간은 별도 필드에 적는다. 시간대는 Asia/Seoul이다.
- `AGENTS.md`는 운영 지침, `log.md`는 추가 전용 이력이므로 YAML을 요구하지 않는다. 형식 검사 때문에 두 파일에 메타데이터를 덧붙이지 않는다.
- 상태는 루트 지침의 유형별 값을 따른다. 프로필·대시보드는 현재 형식인 `recorded`를 유지한다. `reviewed`는 에이전트의 출처 확인 상태다.
- 상대 Markdown 링크를 사용하고 공백은 `%20`으로 인코딩한다. 일반 페이지는 목차 및 관련 출처·주제·질문과 상호 연결한다. 미생성 계획·기록은 일반 텍스트로 표시한다.
- 새 결과와 기존 사용자 진술을 구분한다. 관찰·의료진 설명·문헌 결과·에이전트 추론을 섞지 않는다. 미측정·미기록 값을 0이나 정상으로 채우지 않는다.
- 내용 변경은 관련 부분에 한정한다. 파일 이동·이름 변경이 필요하면 기존 참조를 확인하고 갱신하되, 과거 로그의 링크는 고치지 않는다. 옛 경로에 안내 페이지를 남기는 등 과거 참조를 보존한다.

## 작업 로그의 추가 전용 규칙

**append-only는 기록 단위의 불변성을 뜻한다. 파일 끝에 쓰는 방식이 아니라, 고정 머리말 아래에 새 항목을 삽입하고 기존 항목 전체를 그대로 보존하는 방식이다.**

1. 새 항목은 `# 작업 로그`와 고정 안내문 다음, 기존 첫 `## [날짜]` 항목 바로 앞에 넣는다. 최신 작성 기록이 항상 위에 오며 같은 날짜도 나중에 작성한 항목이 위다.
2. 제목은 `## [YYYY-MM-DD] 작업유형 | 제목`이다. 작업유형은 `ingest`, `query`, `monitor`, `review`, `lint`, `setup` 중 하나다. 날짜는 작업 기록 작성일이다. 과거 사건을 뒤늦게 기록하면 실제 사건 날짜는 본문에 적는다.
3. 본문에는 요청·수행 작업, 출처, 생성·변경한 페이지, 실제 검증 결과, 보류 사항을 필요한 만큼 기록한다. 같은 작업을 여러 스킬이 처리해도 중복 항목을 만들지 않는다.
4. 기존 항목의 제목·본문·링크·공백을 수정하거나 삭제·병합·재정렬하지 않는다. 오래됐거나 잘못된 설명·깨진 링크도 원래 기록을 남기고, 대상 항목의 날짜·제목을 명시한 정정 항목을 새로 추가한다.
5. 추가 직전에 현재 파일을 다시 읽는다. 저장 직전 다른 변경이 생겼으면 최신 파일에 새 항목만 다시 삽입한다. 오래된 사본으로 파일을 덮어써 다른 기록을 없애지 않는다.
6. 저장 후 새 항목을 제외한 기존 내용이 추가 전과 동일한지 확인한다. 기존 항목 수·본문·상대 순서와 파일 머리말을 보존한다. 파일 끝에 추가하거나 전체 정렬·서식 정리로 과거 기록을 바꾸지 않는다.

2026-09-12 전환 작업에서는 사용자의 최신순 변경 요청에 따라 기존 6개 항목의 본문을 보존하고 블록 순서만 한 번 역순으로 바꿨다. 이 전환은 로그에 남기며, 이후 반복 재정렬의 허용 근거로 삼지 않는다.

## 완료 확인

변경한 파일의 메타데이터·출처 위치·상대 링크·목차 설명을 확인한다. 개인 사실이나 실행 상태가 바뀐 경우에만 프로필·대시보드·계획의 일치 여부를 추가 확인한다. 작업 로그에는 기존 기록을 보존한 새 항목 하나를 맨 앞에 남긴다.
