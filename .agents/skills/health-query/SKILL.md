# HealthWiki Query

이 스킬은 HealthWiki 프로젝트에서 사용한다. 위키 루트는 이 스킬 디렉토리의 세 단계 위다. 루트의 `AGENTS.md`, `wiki/index.md`를 읽고 관련 페이지를 찾는다. 개인화할 때만 프로필·관련 계획·최근 기록을 추가로 읽는다.

## 1. 질문을 검색 가능한 형태로 만든다

사용자가 알고 싶은 메커니즘, 비교할 선택지, 내릴 결정을 구분한다. 이미 알려준 목적은 다시 묻지 않는다. 결정에 영향을 주는 미확인 개인 정보만 1~3개 질문으로 묶는다. 답변 전에도 개인 정보에 의존하지 않는 문헌 조사는 진행할 수 있다.

- 통증: 부위·좌우, 유발 운동과 동작 구간, 시작·지속, 강도·기능 영향, 최근 부하 변화, 알려진 진단·의료진 지침 중 필요한 것을 확인한다. 사용자에게 언급된 증상을 근거 없이 특정 손상이나 염증으로 확정하지 않는다.
- 장기 계획: 우선 목표·기간, 현재 상태·운동량, 실행 여건·제약, 확인된 의료진 지침, 모니터링 가능한 지표를 확인한다.
- 식단: 다이어트/근성장/수행능력 중 우선순위, 신체·활동 정보, 현재 섭취·식사 선호·예산·알레르기·관련 건강 조건 중 필요한 것을 확인한다. 정보가 부족하면 계산 가정을 명시한 일반 초안까지만 만든다.

질문 유형에 맞게 대상(P), 중재/노출(I/E), 비교(C), 결과(O), 기간을 정리한다. 기전 질문에 비교군을 억지로 만들지 않는다. 실제 증상에서 위험 신호가 의심되면 최신 공신력 자료를 확인해 의료 평가 안내를 우선하며, 개인 실행안을 완성하려고 필요한 평가를 건너뛰지 않는다.

## 2. 사용할 수 있는 검색 경로를 고른다

### 로컬 분석 스킬 선택

아래 스킬은 이 파일을 기준으로 상대 경로에서 읽는다. 필요한 절차를 실제 수행하기 전에 해당 `SKILL.md`를 읽고, 참고 문서는 이번 질문에 필요한 것만 추가로 읽는다.

| 조건 | 읽을 스킬 | 이 질문에 남길 결과 |
| --- | --- | --- |
| 문헌 탐색·선정 또는 여러 연구의 종합이 필요함 | [literature-review](../literature-review/SKILL.md) | 질문 범위, 선정·제외 기준, 검색식·검색일, 중복 제거, 주제별 근거 종합 |
| 연구·영상·책의 주장을 평가하거나 상충 근거를 비교하고 개인 계획에 적용함 | [scientific-critical-thinking](../scientific-critical-thinking/SKILL.md) | 연구의 강점·한계, 편향·교란·통계·인과 해석, 개인 적용 가능성과 결론의 확실성 |

문헌 조사와 개인 권고를 함께 다루면 두 스킬을 순서대로 적용한다. 단일 논문의 주장 평가처럼 검색이 필요 없는 경우는 비판적 평가만 수행한다. 평가에서 새로운 근거 공백이 드러나면 그 공백에 한해 문헌 탐색으로 돌아간다. 이미 확인한 사용자 목적, 선정 문헌과 추출 결과를 공유하고 인터뷰·검색·결과 저장을 중복하지 않는다.

일반 위키 질의에서는 두 스킬의 관련 분석 단계를 선택해 적용한다. `literature-review`의 정식 리뷰 전체 절차를 수행했다고 표현하지 않는다. 정식 체계적 문헌고찰·메타분석을 요청받으면 해당 스킬의 전체 요구사항과 필요한 도구를 확인하고, 검색·선별 범위, 실제 집계 수, 평가 방법과 미충족 항목을 기록한다. 일부만 수행한 조사는 제한적 문헌 조사로 표시한다.

기존 한국어 Markdown 위키와 주장별 인용 규칙을 유지한다. 일반 질의를 PDF·AI 그림·고정된 데이터베이스 수·새 CLI 설치로 자동 확장하지 않는다. 원 스킬의 전체 산출물 요구는 그 전체 작업을 요청받았을 때 검토한다. `parallel-web`, `scientific-schematics`, API 키 등이 설치된 것으로 가정하지 않는다. 도구가 없으면 현재 가능한 검색·원문 확인 방법으로 진행하고 범위 차이를 남긴다. 스킬 파일 자체가 사라진 경우에도 기존 검색 프로토콜로 가능한 부분을 수행하고 해당 스킬 미적용을 밝힌다.

### 실제 검색 도구 확인

먼저 현재 제공되는 도구·스킬 목록을 확인한다. 논문 검색 전용 기능이 실제 연결되어 있으면 그 기능의 지침을 읽고 이용한다. 검색 서비스의 생성 답변은 후보 탐색에만 쓰고 각 원문을 확인한다. 설치되지 않은 플러그인이나 유료 계정이 있다고 가정하지 않는다.

`literature-review`를 적용할 때는 그 스킬의 `references/core_workflow.md`에서 범위 설정·선별·추출·주제별 종합 절차를 읽는다. 데이터베이스별 문법이나 인용 형식이 필요할 때만 `references/search_and_citation.md`를 추가로 읽는다. 질문에 맞는 검색 범위와 선정·제외 기준을 먼저 정하고, 실제 확인한 문헌과 열람 범위로 종합한다. 프리프린트는 동료심사 여부를 표시하며 출판된 근거와 구분한다.

전용 도구가 없으면 가능한 웹 검색으로 PubMed 및 원문 제공처를 탐색한다. 구체적인 검색·원문 검증 절차는 [검색 프로토콜](references/research.md)을 읽는다. 새로운 API 클라이언트나 검색 서버 설치 없이 현재 도구로 진행한다. 외부 검색이 막히면 기존 위키에서 확인한 범위로 답하고, 새 문헌 검색을 수행한 것처럼 기록하지 않는다.

## 3. 실제 근거를 읽고 비교한다

`templates/source.md`의 인용 규칙을 적용한다. 핵심 주장과 수치에 원문 위치를 연결하고, 초록만 확인한 경우 그 범위로 제한한다. 기존 위키의 결론도 현재 질문에 맞는 출처인지 확인한다. 개인 건강 권고나 최신성에 민감한 사항은 새로 검증한다.

`scientific-critical-thinking`을 적용할 때는 그 스킬의 `references/core_capabilities.md`에서 해당 평가 항목을 읽는다. 편향·통계·근거 수준을 더 살펴야 할 때만 관련 참고 문서를 추가로 읽는다. 핵심 주장과 개인 권고를 좌우하는 연구에 다음을 평가한다.

- 설계와 비교군이 질문에 적합한지, 선택·측정·탈락·선택적 보고 편향이나 교란 요인이 결론에 영향을 주는지.
- 효과 크기·불확실성·다중 비교·결측 처리와 결과의 실제 의미. 비유의 결과를 효과 없음으로 단정하지 않고 관찰 연구나 생리 기전만으로 인과·치료 효과를 확정하지 않는다.
- 연구 대상·중재/부하·기간·결과가 사용자의 조건과 얼마나 맞는지. 강점과 한계를 같은 기준으로 평가하고, 지지·반대 근거를 함께 비교한다.

평가는 원문의 절·표·그림 등 위치를 근거로 적는다. 초록만으로 무작위화·눈가림 등 방법의 적절성을 추정하지 말고 평가 불가 항목을 표시한다. 개별 연구의 편향 위험과 결과별 전체 근거의 확실성을 구분한다. 정식 GRADE·RoB 등 평가를 수행하지 않았다면 도구 이름을 붙인 등급을 생성하지 않는다. 필요해 실제 적용할 때는 적합한 도구·버전·영역별 판단 근거와 제한을 남긴다.

`literature-review`의 `scripts/verify_citations.py`는 필요하고 실행 환경이 갖춰졌을 때 서지 검증을 보조한다. 실행 전 스크립트의 입력·출력·의존성을 확인한다. DOI 해석 성공은 서지 일치나 주장 뒷받침의 증거가 아니므로 제목·저자·연도와 실제 내용을 별도로 대조한다. 실행하지 못해도 직접 원문과 서지를 확인하고 사용한 방법을 적는다.

연구 결과, 메커니즘에 대한 설명, 개인 관찰, 개인 적용 추론을 명확히 구분한다. 가능한 설명을 비교하고 확인에 필요한 정보와 반대 근거도 제시한다. 서지·검색 결과만으로 치료 효과나 확정 진단을 생성하지 않는다.

## 4. 답변과 위키를 연결한다

`templates/query.md`를 사용해 `wiki/queries/`에 질문·개인 맥락·답변·근거 비교·정확한 검색식/검색일·제한을 저장한다. 핵심 결론과 인용은 채팅에도 제공한다.

문헌 탐색·선정·종합 결과는 질문 문서의 검색 이력과 근거 비교에, 개별 연구의 평가 근거는 출처 페이지에, 개인 적용 판단은 질문 문서의 개인 적용 항목에 기록한다. 적용한 스킬·범위와 생략/실행 불가 단계는 검색 이력에 짧게 남긴다. 별도의 중복 리뷰 문서를 만들지 않는다. 원 스킬의 방법론 출처 표기가 필요한 산출물에서는 실제 서지를 확인해 방법/도구 항목에 기록하고, 건강 주장을 뒷받침하는 연구와 구분한다.

새 출처는 `wiki/sources/`에 요약하고 원본을 확보했다면 `raw/`에 새 파일로 보존한다. 원문을 다운로드하지 못해도 검증한 직접 URL과 열람 범위로 출처 페이지를 만들 수 있다. 허가 없이 접근 제한을 우회하지 않는다.

주제 통합은 루트 지침의 목적 인터뷰 조건을 따른다. 현재 질문에 목적이 충분하면 질문 자체를 목적 근거로 기록하고 통합한다. 충분하지 않으면 요약과 질문을 제시하고 pending 출처로 남긴다. 기존 자료는 원본을 바꾸지 않고 링크와 요약을 갱신한다.

계획을 요청받았을 때만 `templates/plan.md`로 초안을 만들고 관찰 지표·재평가·조정 조건을 근거에 연결한다. 식단은 계산식과 가정, 영양소 단위, 생/조리 후 중량을 표시한다. 사용자의 시작 의사 없이 계획을 active로 기록하지 않는다.

목차와 관련 페이지의 링크를 갱신하고 작업 로그에 결과·보류 내용을 추가한다. 개인 관찰이나 실제 계획 상태가 달라진 경우 대시보드도 갱신한다.

## 완료 기준

- 핵심 주장/수치/권고마다 검증한 출처와 열람 위치가 연결되어 있다.
- 사용자에게 필요한 답이 있으며, 검색식·날짜·도구와 접근 한계가 남아 있다.
- 개인화 가정, 추가 확인 사항, 상충하는 근거가 드러난다.
- 질문에 맞는 로컬 스킬이 적용되었으며 문헌 선정·종합과 비판적 평가의 결과, 수행 범위와 한계가 기록되어 있다.
- 목적 답변 대기 자료와 통합된 지식, 계획 초안과 실제 실행이 구분된다.
- 원본은 보존되고 새 페이지의 목차·상호 링크가 연결되어 있다.
