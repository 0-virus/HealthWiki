# 클라이밍 영상 분석

저장소 루트는 이 폴더의 세 단계 위다. 루트 지침, `wiki/index.md`, 최신 `wiki/log.md`, 해당 영상과 연결된 운동 기록·문제별 메모를 먼저 읽는다. 이 스킬 생성 당시의 P08 인물·시간·화면 영역을 다른 영상에 재사용하지 않는다. 영상별 분석은 아래 순서로 수행한다.

## 1. 주 플레이어를 확인받는다 — 필수 대기 단계

1. 지정 영상의 실제 접근 가능 여부, 해상도·회전·프레임 타임스탬프·음성, 등장인물과 시도들을 확인한다. 파일명의 클리어/실패 표시는 아직 사용자 정보일 뿐이다.
2. 주 플레이어 후보가 보이는 **원본 대표 프레임 1–3장과 시간**을 제시한다. 후보를 A/B 등으로 구분하고 옷·화면 위치·행동·등장 시간을 설명한다. 얼굴로 신원을 식별하거나 ‘사용자 본인’이라고 단정하지 않는다.
3. “A: 흰 상의·회색 반바지, 앞부분에서 오른쪽으로 이동하는 사람을 분석 대상으로 할까요?”처럼 **이번 영상의 주 플레이어와 시도**를 사용자에게 확인받는다. 한 명만 등장하더라도 이 확인은 생략하지 않는다. 같은 영상·시도에 대한 명시적 확인 답변이 현재 대화에 이미 있으면 재질문하지 않고 그 답변을 기록한다. 이전 에이전트가 인물을 설명한 것·파일명·묵시적 동의·시간 경과는 확인을 대신하지 않는다.
4. 답변 전에는 원본 조사·후보 프레임·메모 연결·도구 준비만 한다. **분석 영상 생성, 대상별 자세 추정, 실패 원인 리포트는 시작하지 않는다.** 확인 요청 시 이 단계가 사용자가 지정한 절차임을 설명한다.
5. 확인된 설명, 해당 시도, 사용자 답변과 확인 시점을 실행 명세에 남긴다. 다른 인물이나 시도가 새로 분석 대상이 되면 그 대상도 확인받는다. 이미 확인된 인물의 가림이나 잠깐의 미검출 때문에 반복 승인을 요구하지는 않는다.

## 2. 메모와 플레이 구간을 확정한다

- 사용자 메모 원문·작성일·실제 운동일과 연결 문제ID를 유지한다. 특히 어려웠던 동작·쏠림·미끄러짐·의도한 풋워크·피부 손상 등 **사용자 진술과 관찰·가설을 분리**한다. 메모가 없으면 ‘메모 없음’으로 진행하며 만들어 채우지 않는다.
- **시작:** 접근·초크칠을 제외하고, 해당 문제의 시작 홀드/시작 위치에서 스타팅 자세를 취했다고 화면으로 판단되는 첫 프레임. 애매하면 앞뒤 프레임과 경계의 불확실성을 기록한다. 일반적으로 바닥에서 발이 떨어지는 시각과 같다고 가정하지 않는다.
- **클리어 종료:** 탑 홀드를 **두 손으로 터치한 상태에서 안정된 자세를 유지했다고 판단되는 시점**. 첫 손 접촉·순간적인 양손 스침·파일명만으로 완료 처리하지 않는다. 접촉 시작과 안정 판단 시점을 각각 기록하고, 뒤따르는 프레임도 확인하여 판단 근거를 남긴다. 임의의 ‘공식 2초/3초 규정’을 만들지 않는다.
- **실패 종료:** **두 손과 두 발 모두 벽/홀드의 지지를 잃어 실패가 확정된 첫 프레임**. 발만 떨어진 캠퍼싱·스윙은 실패로 확정하지 않는다. 첫 손 미끄러짐과 완전 이탈을 구분한다. 모델 좌표만으로 접촉을 판정하지 말고 원본을 직접 확인한다.
- 영상이 잘리거나 가려져 끝을 볼 수 없으면 `unresolved`로 기록한다. ‘확인 가능한 구간’의 임시 분석은 가능하나 완료/실패 경계를 만들어내지 않는다. 한 파일에 여러 시도가 있으면 시도마다 경계·분석 영상·리포트를 분리한다.
- 시작·종료를 **원본 시간과 실제 프레임 번호**로 저장한다. 내부 번호는 0부터, 사용자 표시 번호는 1부터 세고 둘을 구분한다. 가변 프레임률은 실제 타임스탬프를 사용한다.

## 3. 분석 영상을 생성한다

구체적인 실행 명세·보조 코드·환경 준비는 [실행 안내](references/execution.md)를 읽는다. 제공 스크립트는 한 번의 확인된 시도를 처리한다. 다른 로컬 도구를 사용해도 아래 결과·검증 기준은 유지한다.

- 원본을 보존하고, 파생물은 `analysis-videos/<실제날짜-문제ID>/<새 실행 폴더>/`에 저장한다. 미확인 날짜나 문제ID를 만들어내지 않는다. 기존 결과도 덮어쓰지 않는다.
- 확인된 인물의 손·발·팔꿈치·무릎 위치를 **매 원본 프레임**에서 추정한다. 신체 좌우를 색으로 구분하고 손→팔꿈치→중심, 발→무릎→중심을 연결한다. 골반·어깨·기타 분절은 중심 계산에 사용할 수 있다.
- 중심은 단일 영상 기반 **2차원 무게중심(center of mass) 근사값**이다. 사용한 모델·분절 비율·대리점·좌표계와 한계를 남긴다. 손발 대표점은 접촉점이 아니며, 연결선은 뼈나 힘의 방향이 아니다.
- **현재 프레임의 무게중심만 노란 점으로 표시한다. 과거 위치의 점이나 이동 자취를 영상에 누적하지 않는다.**
- 추정이 없는 프레임은 점을 생략하고, 낮은 신뢰도의 관절·중심은 빈 점·점선으로 구분한다. 직전 좌표 복사·긴 공백 보간·다른 사람으로 추적 전환을 하지 않는다. 여러 후보가 섞이면 해당 구간 추적을 중단하고 ROI 조정·원본 재확인으로 해결한다.
- 좌표는 이미지 평면 기준이다. 카메라가 움직이면 배경 기준 안정화가 신뢰할 만한지 확인한다. 안정화하지 못하면 화면 이동이 섞인 좌표임을 영상·리포트에 표시하고 실제 신체 변위·속도로 해석하지 않는다.
- 자막에는 원본 시간·프레임 번호·플레이 경계·범례·근사/불확실 표시를 포함한다. 원본 전체 길이·시간축·해상도·음성은 유지한다. 별도의 느린 재생본을 만들면 원본 시간과 배속·음성 처리 여부를 표시한다.

## 4. 영상과 메모로 구간별 리포트를 작성한다

**분석 영상 생성·검수 후** [리포트 양식](references/report-template.md)을 사용해 같은 결과 폴더의 `report.md`를 작성한다. 좌표나 자동 템플릿만 보고 서술하지 말고 원본과 오버레이를 함께 본다.

- **기본 분석:** 플레이 시작 시각을 기준으로 `[시작, 시작+1초)`, `[시작+1초, 시작+2초)`처럼 **전체 플레이 구간을 빠짐없이 1초 단위**로 나눈다. 마지막 1초 미만 구간도 포함하고 마지막 행은 종료 프레임까지 포함한다. 같은 자세가 유지돼도 행을 삭제·합치지 않고 유지·미세 조정을 기록한다.
- **중요 구간:** 사용자 메모에서 강조한 구간과 에이전트가 크럭스(crux)로 판단한 구간의 합집합을 **0.1초 단위**로 세분한다. 각 구간의 선택 이유·메모와의 대응·판단 확신을 남긴다. 변화의 전후를 볼 수 있도록 앞뒤 맥락을 포함한다. 메모가 지칭한 시간이 애매하면 후보를 모두 검토하고 대응 불확실성을 적는다.
- 한 행은 해당 시간창 **전체의 변화**를 다룬다. 1초 분석도 처음·중간·끝 프레임과 실제 동작을 확인하며, 0.1초 분석은 가능한 원본 프레임 전부를 확인한다. 30fps라면 보통 0.1초에 3프레임이지만 실제 타임스탬프에 따라 선택한다. 순서가 중요한 이탈/재접촉은 원본 한 프레임 간격으로 추가 확인한다.
- 프레임이 없는 시간창이나 가림은 ‘관찰 불가/미확인’으로 남긴다. 0.1초보다 낮은 원본 시간 해상도를 영상 보간으로 만들어 관찰한 것처럼 쓰지 않는다.
- 각 행에 **손·발 지지/교체, 팔꿈치·무릎과 몸통 자세, 중심 이동 방향·멈춤·회전, 다음 동작과의 관계, 근거 프레임·확신**을 기록한다. 화면 좌우와 신체 좌우를 구분한다.
- 리포트는 사용자 메모 → 화면 관찰 → 해석 → 대안 가설/한계로 연결한다. 실패는 관찰 가능한 이탈 순서와 원인 추정을 구분하고, 악력·집중력·통증·피로·피부 상태를 화면만으로 확정하지 않는다. 성공은 중심 이동과 지지 전환이 완료에 어떻게 이어졌는지 분석하되 효율의 우열을 단정하지 않는다.
- 1초 표와 0.1초 표는 같은 시도의 서로 다른 해상도다. 시간·동작·시도 수를 중복 집계하지 않는다. 정량 수치가 있으면 좌표계·단위·유효 프레임 수·불확실성과 카메라 이동의 영향을 명시한다.

## 5. 검증·저장·전달

- 원본 해시 불변, 출력 전체 디코딩, 프레임 수·PTS·길이·음성, 인물 혼동·좌우·가림·경계, 현재 중심점 표시와 공백 처리, 1초/0.1초 표의 빠짐없는 범위를 확인한다. 시작·종료·크럭스·추적이 약한 구간의 표본 이미지를 직접 본다. 검출 성공률을 위치 정확도로 보고하지 않는다.
- 코드가 생성한 시간창은 관찰 리포트가 아니다. **모든 필수 행의 실제 분석을 작성**한 뒤 완료 처리한다. 미해결 구간은 내용과 이유를 표시하고 성공/실패 결과를 과장하지 않는다.
- 기본 산출물: 오버레이 영상, 프레임별 중심·관절 좌표/신뢰도와 메타데이터, 플레이/중요 구간 명세, 구간별 리포트, 검증 요약. 기존 위키의 개인 사실·운동 횟수를 자동으로 바꾸지 않는다. 이 워크플로의 기본 저장은 분석 폴더와 작업 로그 하나이며, 위키 본문 통합은 별도 요청이 있을 때만 한다.
- 채팅에 주 플레이어·플레이 경계·핵심 동작/실패 원인과 한계, 영상·리포트 링크를 전달한다. 주 플레이어 확인 후 다시 일괄 승인 단계를 추가하지 않는다.
