# 실행 안내

이 문서는 [분석 절차](../SKILL.md)의 실행 보조 자료다. 인물 확인과 원본 관찰을 마친 뒤 사용한다. 스크립트는 분석 영상과 검토용 시간창을 만들며, 동작 리포트의 관찰·해석은 에이전트가 직접 작성한다.

## 준비와 입력

1. 원본의 메타데이터와 실제 프레임을 열어 후보 인물·시도를 확인받는다. 확인 전에는 자세 추정이나 렌더링을 실행하지 않는다.
2. 확인 후 스타팅 자세, 양손 탑 접촉 및 안정 판단 또는 네 팔다리의 완전 이탈을 원본에서 확인한다. 시작·종료 프레임과 근거를 기록한다. 주요 구간은 메모와 실제 크럭스를 함께 검토하여 선택한다.
3. `request.json`에 아래 구조를 채운다. **다음은 실행 가능한 실제 분석 정보가 아닌 양식**이다. `confirmed`를 확인 답변 없이 바꾸지 않으며 예시 프레임·시간도 실제 관찰로 교체한다.

```json
{
  "source": "원본의 절대경로 또는 request.json 기준 상대경로.mp4",
  "source_sha256": "원본 파일의 SHA-256",
  "player": {
    "confirmed": false,
    "description": "옷·화면 위치·해당 시도",
    "confirmation_text": "",
    "confirmed_at": ""
  },
  "memo": {
    "source": "연결 기록의 경로·문제ID 또는 채팅",
    "event_date": "미확인",
    "recorded_at": "미확인",
    "text": "실제 메모 원문 또는 메모 없음"
  },
  "roi": [0.0, 0.0, 1.0, 1.0],
  "camera_note": "고정/이동 여부와 배경 대비 확인 결과",
  "play": {
    "start_frame": 0,
    "end_frame": 60,
    "outcome": "unresolved",
    "start_evidence": "스타팅 자세를 판단한 화면 근거 또는 경계 미확인 사유",
    "end_evidence": "양손 탑 접촉 뒤 안정/손발 모두 이탈/미확인 근거"
  },
  "critical": [
    {"start_s": 1.0, "end_s": 1.5, "origin": "memo", "reason": "실제 메모와 대응하는 관찰 근거"}
  ]
}
```

- `confirmed_at`: 사용자 확인 시각과 시간대. 확인 문구는 실제 답변을 보존한다.
- `start_frame`, `end_frame`: 전체 원본에서 **0부터** 세는 프레임 번호, 양 끝 포함. 완료 상태는 `cleared`, `failed`, `unresolved` 중 하나다. 양손 접촉 시작 시각과 안정 판단 시각은 리포트에 각각 남긴다.
- `critical`: 원본의 초 단위 타임스탬프. 플레이 안에 있는 구간만 지정한다. `origin`은 `memo`/`crux`/`both`이며, 이유에 관찰 근거와 확신을 남긴다. 해당 구간이 없다고 판단할 때만 빈 배열을 쓴다. 겹치거나 맞닿는 구간은 합친 뒤 0.1초 간격으로 나눈다.
- `roi`: 이미지 너비·높이에 대한 비율 `[왼쪽, 위, 오른쪽, 아래]`. 확인한 인물의 전 동작을 포함하되 다른 사람의 유입을 피한다. 잘리는 팔다리가 없는지 검수한다. 화면 전체 값은 대상 분리를 확인한 경우에만 사용한다.
- `source_sha256`: 실제 파일 바이트로 계산한다. 출력 명세의 원본 경로는 재실행 가능하도록 절대경로로 저장된다. 다른 PC로 옮기면 경로를 다시 지정하되 해시는 유지한다.

## 로컬 환경과 명령

기존 설치를 먼저 확인한다. 검증한 조합은 Python 3.12, MediaPipe 0.10.32, OpenCV headless 4.13.0.92, PyAV 18.1.0, NumPy 2.3.3, Pillow다. 새 환경이 필요한 경우 가상 환경에 설치하며 모델·환경·영상은 스킬에 포함하거나 외부 서비스에 업로드하지 않는다.

저장소 루트에서 Windows PowerShell 예시:

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install mediapipe==0.10.32 opencv-python-headless==4.13.0.92 av==18.1.0 numpy==2.3.3 Pillow
```

기존 작업의 임시 의존성 경로는 새 PC에서 존재한다고 가정하지 않는다. macOS/Linux는 가상 환경의 `bin/python`을 사용하고 `--font`에 설치된 TrueType 글꼴 경로를 준다. Windows 기본 글꼴은 `C:/Windows/Fonts/malgun.ttf`다.

자세 추정 모델은 [공식 Pose Landmarker Heavy](https://storage.googleapis.com/mediapipe-models/pose_landmarker/pose_landmarker_heavy/float16/1/pose_landmarker_heavy.task)를 로컬 모델 폴더에 내려받는다. 다운로드는 모델에 한하며 개인 영상은 로컬에서 처리한다. 버전·모델 해시는 실행 결과에 남긴다.

```powershell
.venv/Scripts/python.exe .agents/skills/climbing-video-analysis/scripts/analyze_video.py --manifest request.json --model C:/local-models/pose_landmarker_heavy.task --out analysis-videos/날짜-문제ID/run-01
.venv/Scripts/python.exe .agents/skills/climbing-video-analysis/scripts/test_analyze_video.py
```

경로는 실제 환경에 맞춘다. `--out`은 **아직 존재하지 않는 새 폴더**여야 한다. 원본·기존 출력 덮어쓰기는 거부한다. 실패한 실행의 폴더는 미완료로 남기고 새 실행 경로로 재시도한다.

모델을 다시 실행하지 않고 검수한 좌표를 재사용할 때는 `--model` 대신 `--pose-cache 이전실행/pose-data.npz`를 지정할 수 있다. 원본 해시와 타임스탬프·배열 크기를 검증한다. **같은 원본이라는 사실만으로 대상 인물이 같지는 않다.** 이전 명세의 확인된 인물·시도·ROI·유효 추정 구간이 이번 실행과 맞는지 먼저 비교한다. 이전 캐시 밖의 동작이나 다른 사람으로 확대할 때는 다시 추정한다. 옛 P08 캐시에는 새 형식의 시간·해시 결합 정보가 없으므로 그대로 넘기지 않는다.

## 추정과 표시의 의미

- MediaPipe의 33개 랜드마크 중 손은 손목·새끼손가락·검지 평균, 발은 뒤꿈치·발끝 평균, 팔꿈치·무릎은 해당 관절을 쓴다. 이 점은 실제 홀드 접촉점이 아니다. 신체 왼쪽 청록, 오른쪽 분홍, 중심 노랑이다.
- 아래 분절 질량의 합은 1이다. 분절 대표점의 이미지 좌표를 질량으로 가중 평균한다. 비율 `r`은 첫 점에서 둘째 점으로 향하는 위치다.

| 분절 | 질량 비율 | 이미지 대표점 |
| --- | --- | --- |
| 머리·목 | 0.081 | 양 귀 중점 |
| 몸통 | 0.497 | 골반 중점 → 어깨 중점, r=0.495 |
| 위팔, 좌우 각각 | 0.028 | 어깨 → 팔꿈치, r=0.436 |
| 아래팔·손, 좌우 각각 | 0.022 | 팔꿈치 → 손목, r=0.682 |
| 넓적다리, 좌우 각각 | 0.100 | 골반 관절 → 무릎, r=0.433 |
| 종아리, 좌우 각각 | 0.0465 | 무릎 → 발목, r=0.433 |
| 발, 좌우 각각 | 0.0145 | 발목 → 발끝, r=0.500 |

이전 P08 작업의 Dempster 12분절 근사를 재사용한다. 해부학적 기준점을 모델 랜드마크로 대체한 **2D 추정**이며 개인 신체 비율·질량·3D 위치를 실측하지 않는다. 원근 투영에서는 이 가중 평균이 실제 3D 중심의 정확한 투영과 같지 않다.

랜드마크 품질은 visibility와 presence의 최솟값을 사용한다. 중심 품질은 사용 분절의 점수 가중 평균이며 정확도 확률이 아니다. 기본 경계 0.6 미만은 회색/빈 점·점선으로 구분한다. 필요한 랜드마크가 없으면 해당 프레임 좌표를 비워 둔다. 이전 좌표 복사·시간 보간으로 채우지 않는다. 현재 프레임의 중심만 노란 점으로 표시하며 과거 위치를 화면에 누적하지 않는다.

ROI 안에서 여러 자세가 검출되면 `ambiguous`로 표시하여 어느 하나를 임의로 선택하지 않는다. **단일 검출도 신원 추적의 보장은 아니다.** 가림 전후와 인물 교차는 원본으로 확인하고, 다른 인물이 잡혔으면 해당 좌표를 폐기한 뒤 ROI·구간 분리 등으로 재처리한다. 자동 검출만으로 인물 확인이나 완등/실패 판정을 대신하지 않는다.

모든 좌표는 원본 이미지의 픽셀, x 오른쪽·y 아래쪽이다. 카메라 움직임은 스크립트가 보정하지 않는다. 움직이는 카메라는 안정화 파생본을 별도로 검수하거나 화면 좌표 분석으로 범위를 제한한다. 점 간 거리를 미터·실제 속도·손발 하중으로 환산하지 않는다.

## 출력과 검수

| 파일 | 용도 |
| --- | --- |
| `overlay.mp4` | 전체 원본 프레임·해상도·시간축·음성을 유지한 오버레이 |
| `manifest.json` | 확인 답변·메모·ROI·플레이 경계·중요 구간 |
| `pose-data.npz` | 프레임별 33개 점의 x/y/품질, PTS, 원본 해시 |
| `centers.json` | 프레임별 중심·품질·추적 상태 |
| `segments.json` | 1초/0.1초 시간창과 실제 원본 프레임 번호·검토 이미지 대응 |
| `review/*.jpg` | 주 플레이어 ROI의 원본 검토 이미지. 1초 창은 처음·중간·끝, 0.1초 창은 모든 원본 프레임 |
| `validation.json` | 전체 디코딩·시간축·길이·음성 바이트·원본 보존 검증과 한계 |
| `report.md` | **영상 검수 후 에이전트가 작성할** 메모 기반 동작 리포트 |

시간창은 마지막 행을 제외하고 끝 시각을 포함하지 않는다. 마지막 행에는 종료 프레임을 포함한다. 프레임이 없는 0.1초 창은 그대로 남긴다. 선택된 이미지 몇 장만으로 동작을 추정하지 말고 영상과 필요한 중간 프레임도 확인한다. 자동 디코딩과 실제 시각 열람 범위를 구분한다.

스크립트는 회전 메타데이터·가변 해상도·다중 비디오 스트림·누락/역전 타임스탬프·홀수 해상도를 자동 변경하지 않고 오류로 알린다. 이 경우 원본을 보존한 정규화 파생본을 따로 만들고 원본과 시간·회전 대응을 확인한 뒤 사용한다. VFR은 실제 PTS를 유지한다. 밀리초로 구분되지 않는 프레임은 모델 입력 제한 때문에 별도 처리 방법이 필요하다. MP4에 음성을 그대로 담을 수 없거나 길이/PTS 검증에 실패하면 완료로 보고하지 말고 호환 형식 또는 명시적으로 기록한 음성 변환으로 해결한다.

완료 전에 시작·중간·크럭스·이탈/완등·가림·다른 사람이 나오는 지점의 원본/오버레이를 직접 비교한다. 현재 중심점만 표시되는지, 낮은 품질·미검출 구간에 거짓 점이 생기지 않는지 확인한다. 자동 검증 성공은 이러한 시각 검수와 리포트 작성을 대신하지 않는다.
