# Query — 위키에 묻고 결과를 축적

위키 루트는 이 스킬 폴더의 세 단계 위다. 아래 경로는 루트 기준이다. `AGENTS.md`, `wiki/index.md`를 먼저 읽고 질문과 관련된 주제·출처·이전 분석을 찾는다. 개인 적용에는 관련 프로필·계획·관찰 기록만 추가로 읽는다.

## 기존 지식부터 확인

사용자의 질문, 원하는 결정/비교, 결과 형식을 확인한다. 답이 달라질 정도로 범위가 모호할 때만 짧게 질문한다. 이미 제공된 목적과 개인 정보를 다시 묻지 않는다.

목차의 관련 페이지를 읽고 상호 링크를 따라간다. 필요한 경우 현재 환경의 텍스트 검색으로 동의어·전문 용어·연관 개념을 찾는다. 목차의 한 줄 요약만으로 답하지 않는다. 관련 출처와 주장 위치를 확인하며 기존 지식으로 충분한 부분을 다시 조사하지 않는다.

위키가 비어 있거나 근거가 부족하면 그 사실을 밝힌다. 질문의 전제를 검증하지 않은 채 사실로 받아들이지 않는다. `pending` 출처와 미검증 설명은 검증된 주제 지식과 구분한다.

## 필요한 경우 외부 근거 보완

새 논문 검색·건강 근거 검증·개인 식단/통증 관리 계획이 필요하면 [health-query](../health-query/SKILL.md)를 읽고 그 절차로 질문을 끝까지 처리한다. 여기서 확인한 맥락을 이어 쓰고 저장·목차·로그 갱신은 한 번만 한다. `health-query`는 전문 조사 절차이며 이 스킬은 기존 위키 질의를 포함하는 진입점이다.

기존 내용을 설명·비교하는 데 충분한 근거가 있으면 아래 절차로 답한다. 개인 건강 권고나 최신성에 민감한 결론은 기존 문서만으로 최신이라고 단정하지 말고 새로 검증한다. 사용자가 외부 검색을 금지하면 저장된 근거와 날짜의 한계를 밝히고 새로운 개인 권고를 확정하지 않는다.

## 답과 연결을 만든다

1. 결론을 먼저 제시하고 `templates/source.md`의 규칙대로 핵심 주장에 출처 페이지와 원문 위치를 연결한다. 개인 관찰, 문헌 결과, LLM의 종합·추론을 구분한다.
2. 자료 간 공통점·차이·모순과 개인 적용의 한계를 설명한다. 출처가 뒷받침하지 않는 수치나 확신을 추가하지 않는다. 원문에 접근하지 못한 경우 실제 열람 범위를 표시한다.
3. 기본 결과는 한국어 Markdown이다. 비교에는 표를 쓰고, 사용자가 요청한 차트·캔버스·발표 자료 등은 현재 가능한 도구로 만든 뒤 근거와 함께 연결한다. 형식 요청이 없으면 추가 산출물을 만들지 않는다.
4. `templates/query.md`로 `wiki/queries/YYYY-MM-DD-주제.md`에 답과 근거를 저장한다. 반복 질문은 기존 분석을 확인해 필요한 갱신만 하고, 결론이 바뀌면 이유와 날짜를 남긴다. 사용자가 저장을 원하지 않으면 관련 파일과 작업 로그도 쓰지 않고 답만 제공한다.
5. 검색하지 않았다면 `외부 검색 없음 — 기존 위키 조회`와 읽은 페이지를 기록한다. 실행하지 않은 검색식·날짜·도구·출처를 만들어 채우지 않는다. 적용되지 않는 템플릿 항목은 생략한다.
6. 새로 확인한 연결이나 종합이 기존 주제를 개선하면 해당 주제도 갱신한다. 새 자료 통합은 [ingest](../ingest/SKILL.md)의 목적 확인 조건을 따른다. 현재 질문으로 목적이 충분하면 반복 인터뷰 없이 그 질문을 근거로 기록한다.

## 마무리

새 분석을 목차에 한 줄 설명과 함께 연결하고 관련 주제·출처·계획과 상호 링크를 만든다. 실제 개인 기록·계획 상태가 변한 경우만 대시보드를 갱신한다. 작업 로그에 `query` 항목과 사용한 근거·변경 페이지·남은 질문을 추가한다.

채팅에는 질문의 답, 핵심 출처, 저장한 결과 링크를 제공한다. 새로운 질문이나 자료 탐색 제안은 현재 답의 공백과 연결해 제시한다.
