# 운동 기록

위키 루트는 이 폴더의 세 단계 위다. 루트와 wiki 지침, [전체 목차](../../../wiki/index.md), [운동 기록 안내](../../../wiki/workouts/index.md), 해당 종목 양식과 기존 날짜 기록을 읽는다. 개인 관찰을 연결할 때 프로필·대시보드·관련 일별 기록을 확인한다.

## 종목과 양식 선택

등록된 종목·저장 경로·양식의 기준은 [운동 기록 안내의 등록 종목](../../../wiki/workouts/index.md#등록-종목)이다. 여기서 종목은 크로스핏·클라이밍 같은 활동 종류이며, WOD에 처음 나오는 개별 동작마다 새 폴더를 만들지 않는다.

- 크로스핏은 [크로스핏 양식](../../../templates/workout-crossfit.md)을 적용한다. 사전 운동이 제공되면 WOD 앞에 두고, 운동 내용은 영어로 번역한다(메모는 한국어로 작성). 순서·줄바꿈·번호·묶음·괄호를 최대한 유지한다. 새 표나 슬래시 표기를 강제해 사용자의 입력 형태를 바꾸지 않는다.
- 클라이밍은 [클라이밍 양식](../../../templates/workout-climbing.md)을 적용한다. 날짜·지점·총 시간, 색상별 클리어 수, 개별 문제의 메모·사진·영상 관계를 기록하며 아래 지점 확인 절차를 먼저 따른다.
- 미등록 종목은 먼저 입력을 바탕으로 필요한 항목·단위·언어·배치·첨부 경로를 정해 `templates/workout-종목.md`를 만든다. 형식 선택에 중요한 정보가 부족할 때만 짧게 질문하고, 이미 사용자가 정한 내용은 다시 묻지 않는다. 정한 형식을 안내에 등록하고 해당 종목 폴더에 첫 기록을 저장하며 결과에서 새 형식을 알린다. 다른 종목 양식을 임의로 재사용하지 않는다.

## 클라이밍 지점과 난이도 확인

지점별 홀드 스티커 색상의 난이도 순서는 [지점별 난이도 등록부](../../../wiki/workouts/climbing/venues.md) 한 파일에서 관리한다. 지점마다 정식 이름, 사용자에게 확인한 별칭, 위치, 쉬움 → 어려움 색상 순서, 출처·열람일, 사용자 확인일을 남긴다. 홀드 자체의 색과 난이도 스티커 색을 혼동하지 않는다.

- 매 기록에서 입력 지점명을 등록부의 **확인 완료된 정식 이름·별칭**과 대조한다. 앞뒤 공백과 연속 공백만 정리해 유일하게 일치하면 해당 지점에 연결한다. 브랜드명만 같거나 지점명이 비슷한 경우, 후보가 여러 개인 경우, 미등록 약칭·오탈자는 자동 매칭하지 않고 반드시 사용자에게 재확인한다. 확인 대기 후보를 등록된 지점으로 취급하지 않는다.
- 새 지점은 웹 검색으로 지점명·주소와 해당 지점의 색상 난이도표를 조사한다. 공식 안내를 우선하고 출처 링크·열람 범위·최신성 한계를 남긴다. 검색 결과의 **지점과 쉬움 → 어려움 순서를 사용자에게 제시해 확인받은 뒤** 정식 등록한다. 다른 지점·브랜드 공통표를 그대로 적용하지 않으며, 검색 실패·자료 충돌·누락은 명시하고 사용자에게 정확한 정보를 확인한다.
- 답변 전에도 운동은 입력 지점명·색상·개수를 보존해 임시 저장할 수 있다. 등록부에는 확인 대기 후보를 별도로 두고, 지점 연결·난이도 순서 적용은 보류한다. 확인 후 기존 세션과 후보를 갱신하며 같은 지점을 중복 생성하지 않는다.
- 지점의 체계가 바뀌거나 기존 색상표와 다른 입력이 오면 확인 후 적용 날짜·이전 순서·변경 근거를 보존한다. 과거 운동을 새 체계로 소급 환산하거나 서로 다른 지점의 같은 색을 동일 난이도로 해석하지 않는다.

## 날짜·추가·정정

- 파일은 실제 운동일 `YYYY-MM-DD.md`, 같은 날 별도 세션은 `YYYY-MM-DD-02.md` 순으로 저장한다. 같은 세션의 추가 입력이면 기존 파일에 보완한다. 같은 날짜라는 이유로 새 세션을 덮어쓰지 않는다.
- 사건 날짜와 작성 날짜를 구분하고 Asia/Seoul을 적용한다. 상대 날짜는 기준일과 환산 근거를 남긴다. 날짜를 확정할 수 없으면 확인하며 임의의 운동일을 만들지 않는다.
- 일반 위키 YAML에 `date`, `sport`를 더한다. `type: observation`, `status: recorded`, 실제 작성일의 `created`·`updated`를 쓴다. 종목별 추가 필드는 해당 양식을 따른다.
- 사용자가 제공한 수치·단위·좌우·시간 제한을 유지한다. 미제공 무게, 실제 완료 시간, 라운드, 총량을 추정하지 않는다. 기재된 WOD와 실제 수행 결과를 구분한다.
- 원래 진술과 정정 근거를 보존한다. 운동 분석·의학적 해석은 기록 본문과 구분하고, 단순 저장을 위해 목적 인터뷰나 건강 근거 검색을 추가하지 않는다. 클라이밍 새 지점 등록의 웹 검색·사용자 확인은 위 절차를 따른다. 템플릿용 예시는 실제 운동 이력으로 저장하지 않는다.

## 첨부와 연결

- 클라이밍 글은 `wiki/workouts/climbing/records/`, 실제 제공된 사진·영상은 `wiki/workouts/climbing/assets/`에 둔다. 첨부를 바꾸거나 압축해 원본을 덮어쓰지 않는다. 기존 raw 자료는 이동하지 않고 링크하거나 필요한 사본을 둔다.
- 클라이밍 영상 제목·파일명은 `yyyy-mm-dd 지점명 섹터 난이도색상홀드색상.ext`로 저장한다. 예: `2026-09-20 서울숲클라이밍 잠실점 섹터1 남색노랑.mp4`. 사용자 요청의 괄호는 플레이스홀더 표시이므로 실제 제목·파일명의 지점명·섹터·색상에는 넣지 않는다. 지점명은 확인된 등록명을 쓰며, 난이도 스티커 색 다음에 홀드 자체 색을 공백 없이 붙인다. 원본 확장자를 유지하고 실패 영상은 색상 뒤에 공백과 `(실패)`를 붙여 결과 표시의 괄호를 유지한다. 섹터·색상은 제공된 파일명·사용자 설명·실제로 확인한 영상에 근거하며 애매하면 질문한다. 확인 전 이동이 필요하면 미확인 필드를 명시하고 원래 제목을 기록한다.
- 같은 제목의 다른 영상은 확장자 앞에 `-02` 등 접미사를 붙여 보존한다. 기록에는 원래 파일명·새 제목·실제 상대 링크·문제ID를 남기고 동일 문제의 성공·실패 영상은 같은 문제ID에 연결한다. 미제공 첨부의 가짜 파일·링크를 만들지 않는다.
- 사용자가 외부 폴더에서 **이동**을 요청하면 대상 파일을 특정하고 기존 첨부와 충돌을 확인한 뒤 복사본만 남기는 대신 원본을 이동한다. 이동 전후 크기·해시 일치와 원래 경로에서 파일이 없어졌는지 확인한다. 폴더 내 무관한 파일은 건드리지 않으며, 기존 raw·보관된 첨부 원본의 보존 원칙은 유지한다.
- 영상은 실제 확인한 구간과 사용자 설명을 구분한다. 파일을 받았다는 사실만으로 내용이나 클리어 여부를 추정하지 않는다. 첨부만 나중에 오면 연결할 세션·문제를 확인해 기존 기록을 보완한다.
- 운동 상세는 종목별 파일을 기준으로 유지한다. 통증·식사 등 일별 관찰은 `monitoring/daily/`에 두고 상호 링크한다. 동일 운동을 일별 관찰과 운동 파일에서 두 번 집계하지 않는다. 단순 운동 기록마다 빈 일별 관찰을 만들 필요는 없다.

## 마무리

운동 안내와 전체 목차에 각 실제 기록의 링크·한 줄 설명을 추가한다. 새 양식은 양식 안내에도 등록한다. 개인 상태가 달라졌을 때만 프로필·대시보드를 갱신한다. 상대 링크·날짜·메타데이터·첨부 대응을 확인하고, 로그 규칙에 따라 `monitor` 항목 하나를 맨 앞에 추가한다. 형식만 구축한 작업은 `setup`으로 남긴다.
