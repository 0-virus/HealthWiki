YAML date는 실제 운동일, created·updated는 실제 작성일이다. venue는 정확한 지점명 문자열, duration_minutes는 분으로 환산 가능한 총 시간이다. 예: 2시간 → 120. 알 수 없으면 YAML 값은 비워 두고 본문에 미기록으로 쓴다. 본문의 원래 시간 표현은 유지한다.
색상은 해당 지점에서 사용한 이름 그대로 보존하며 다른 지점의 색상이나 V등급으로 환산하지 않는다. 합계와 문제별 상세를 별도 클리어로 중복 집계하지 않는다.
지점명은 [지점별 난이도 등록부](../wiki/workouts/climbing/venues.md)와 대조하고 운동 기록 스킬의 확인 절차를 따른다. 애매한 매칭은 반드시 재확인하며 새 지점은 웹 검색 후 지점·순서를 사용자에게 확인받는다. 확인 전에는 입력명을 보존하고 지점·난이도 확인 대기로 쓴다. 확정 후 venue에 등록명을 쓰되 원래 입력명도 본문에 남긴다.
임시 저장도 observation의 status는 recorded로 두고 본문에 영상·지점 등 보완 대기 항목을 적는다. ‘영상 없음’과 ‘미첨부·업로드 대기’를 구분한다.
문제ID는 세션 안에서 P01, P02처럼 부여하며 이후 제목·색상·첨부가 보완돼도 유지한다. 개별 문제 정보가 아직 없으면 문제별 절은 생략한다. 색상별 개수만으로 개별 문제의 특징이나 시도 횟수를 만들지 않는다. 이후 사진 등이 오면 합계에 포함된 문제인지 새 클리어인지 구분한다.
사진·영상은 각각 제목과 실제 상대 링크를 적는다. records/에서 assets/의 파일로 가는 링크는 ../assets/파일명.ext이다. 한 문제에 여러 첨부를 연결할 수 있다. 실제 받은 파일만 링크하며 공백은 %20으로 인코딩한다.
영상 파일명은 지점명·섹터·색상의 괄호 없이 `yyyy-mm-dd 지점명 섹터 난이도색상홀드색상.ext`를 사용한다. 예: `2026-09-20 서울숲클라이밍 잠실점 섹터1 남색노랑.mp4`. 확인된 등록 지점명·섹터를 쓰고 스티커 난이도 색과 홀드 색을 순서대로 붙인다. 실패 영상은 색상 뒤에 공백과 `(실패)`를 붙여 결과 표시의 괄호를 유지한다. 원래 파일명도 기록하며 같은 문제의 여러 시도는 동일 문제ID로 묶는다. 이동 요청 시 파일 이동·원본 검증은 운동 기록 스킬을 따른다.
예시(실제 운동 이력이 아님): 날짜 2026-03-03, 서울숲 클라이밍 잠실새내점, 총 운동시간 2시간, 파랑 3개·보라 2개. 이 경우 요약 표에 파랑 3, 보라 2를 쓰며 개별 상세는 추후 입력 시 추가한다.
